# PulseCortex

PulseCortex is a local TypeScript daemon that lets one paired owner control allowlisted Codex sessions from Feishu direct messages. Feishu event delivery and card callbacks use outbound WebSocket long connections. Codex clients share a loopback-only app-server listener so the terminal and Feishu can control the same live thread.

The daemon supports one host, one owner, concurrent sessions in locally registered projects, and both PulseCortex-created and shared-runtime Codex sessions. It does not expose an arbitrary shell endpoint; commands, edits, network requests, and approvals originate in `codex app-server`.

## Privacy Warning

Prompts, agent messages, source excerpts, command summaries, diffs, test results, and any output you request from `/logs` leave the workstation through Feishu. Every successful outbound Feishu text/card delivery is also written to the daemon log without signed action tokens. Built-in and configurable redaction is defense in depth, not a guarantee. Do not use PulseCortex with repositories or credentials that your Feishu tenant is not authorized to receive.

## Requirements

- Node.js 25.9.0 or newer and pnpm 11
- An installed, authenticated Codex CLI `0.147.x`
- A Feishu enterprise self-built application with bot capability
- Outbound internet access to Feishu and the model provider

The app-server protocol snapshot in `packages/codex-driver/src/generated` was generated by Codex CLI `0.147.0`. Startup rejects a different CLI series rather than guessing at protocol compatibility.

## Installation

### Windows

```powershell
pnpm install
pnpm build
pnpm pulsectl init
```

### Linux

```bash
pnpm install
pnpm build
pnpm pulsectl init
```

On Linux, `pulsectl init` stores state in
`$XDG_STATE_HOME/pulsecortex` or `~/.local/state/pulsecortex` by default and
creates the secret environment file with mode `0600`.

### Configure Feishu

1. Open the [Feishu Developer Console](https://open.feishu.cn/app) and create an
   **enterprise self-built application**. PulseCortex requires an application
   bot, not a one-way custom webhook bot.
2. Open **Add Capabilities** and enable **Bot**.
3. Open **Permissions & Scopes** and grant only these application-identity
   permissions:
   - `im:message.p2p_msg:readonly` - read direct messages sent to the bot.
   - `im:message:send_as_bot` - send and update messages as the bot.

   Do not grant group-message permissions for the single-owner release.
4. Open **Credentials & Basic Information** and copy the App ID and App Secret
   into the environment file whose path was printed by `pulsectl init`:

   ```dotenv
   FEISHU_APP_ID=cli_your_app_id
   FEISHU_APP_SECRET=your_app_secret
   PULSECORTEX_ACTION_SIGNING_KEY=your_random_signing_key
   ```

   Generate the signing key locally with:

   ```powershell
   node -e "console.log(require('node:crypto').randomBytes(48).toString('base64'))"
   ```

   Keep these values out of `config.json`, SQLite, logs, command arguments, and
   this repository.
5. In a separate terminal, start the daemon with `pnpm start` so Feishu can
   detect its outbound WebSocket connection.
6. Open **Events and Callbacks > Event Configuration**, select **Long
   Connection**, and subscribe to `im.message.receive_v1`.
7. Open **Events and Callbacks > Callback Configuration**, select **Long
   Connection**, and subscribe to `card.action.trigger`.
8. Create and publish an application version. Restrict the application's
   availability to the intended owner during initial testing. Permission,
   subscription, and availability changes do not take effect until published.
   Restart the daemon after publishing.

If the console refuses to save long-connection delivery, leave `pnpm start`
running and retry. No public URL, webhook endpoint, firewall rule, or inbound
port is required. See the [detailed Feishu setup guide](docs/feishu-setup.md)
for troubleshooting and the trial checklist.

### Register a project and pair the owner

Register each project locally. Feishu messages can select these names but can never submit a path.

Windows:

```powershell
pnpm pulsectl project add pulsecortex E:\Projects\PulseCortex
pnpm pulsectl diagnose
pnpm pulsectl pair
```

Linux:

```bash
pnpm pulsectl project add pulsecortex /home/your-user/projects/PulseCortex
pnpm pulsectl diagnose
pnpm pulsectl pair
```

Start the daemon with `pnpm start`, direct-message `/pair <code>` to the bot, then use `/projects` or `/new pulsecortex`. Daemon events are formatted for terminal reading and saved below the data directory as `daemon.log` (readable) and `daemon.jsonl` (structured). During development, `pnpm dev` runs the TypeScript source directly.

List registered projects or remove one by its name without deleting its files:

```powershell
pnpm pulsectl project list
pnpm pulsectl project remove pulsecortex
```

PulseCortex remembers the most recently selected project in `settings.json` below its data directory. On the next daemon start it prefers that project's newest controllable Codex session, or uses the project for the next task when no session is running. Inspect or override local preferences with:

```powershell
pnpm pulsectl settings list
pnpm pulsectl settings set default-project pulsecortex
pnpm pulsectl settings set auto-start-on-boot true
```

After building, install the reversible shell integration once.

Windows:

```powershell
pnpm pulsectl shell install
```

The Windows installer updates the user PATH and adds marked, reversible entries
to the current user's PowerShell profiles. Open a new terminal after installing.

Linux:

```bash
pnpm pulsectl shell install
export PATH="${PULSECORTEX_DATA_DIR:-${XDG_STATE_HOME:-$HOME/.local/state}/pulsecortex}/bin:$PATH"
```

Add the printed PulseCortex `bin` directory to your shell profile to make that
PATH change persistent. If `config.json` overrides `dataDir`, use the directory
printed by `shell install` instead of the default above.

Run `codex` normally after completing the platform-specific setup. Interactive, resume, fork, archive, and delete commands automatically use the loopback PulseCortex app-server; maintenance and non-interactive commands continue to use Codex directly. If the daemon is unavailable, the shim prints a warning and launches standalone Codex. `pnpm pulsectl codex` remains an explicit fallback; without a project argument it uses the remembered project first and only then infers from the current directory.

Codex sessions already connected to the PulseCortex shared app-server are rejoined automatically, including sessions that were running before PulseCortex discovered them. A session active in a separate standalone app-server cannot be adopted mid-turn because Codex enforces a single runtime writer for each thread. PulseCortex detects and reports that condition proactively in Feishu, avoids creating a duplicate for the chosen project, and tells the owner to relaunch through `pnpm pulsectl codex <project>` or the installed shell integration.

Install user-level startup after building.

Windows uses a per-user Task Scheduler task and falls back to the user's Startup
folder when Task Scheduler is unavailable:

```powershell
pnpm pulsectl service install
pnpm pulsectl service status
```

Linux uses a systemd user unit and therefore requires a working
`systemctl --user` session:

```bash
pnpm pulsectl service install
pnpm pulsectl service status
```

See [Feishu setup](docs/feishu-setup.md), [operations](docs/operations.md), [security](docs/security.md), and [architecture](docs/architecture.md).

## Remote Commands

| Command | Behavior |
| --- | --- |
| `/projects` | Select a locally registered project |
| `/new [task]` | Create a concurrent session in the chosen project and optionally start work; use `/new <project> [task]` to override it |
| `/sessions` | Discover sessions in registered projects, three per page with 100-word previews and Show more navigation |
| `/instructions` | Choose one of Codex's built-in instruction presets using a Feishu card; creates a session when none is selected |
| `/resume [session-id]` | Resume or select an allowlisted session |
| `/send <message>` | Start or steer work in the selected session; create one if none is selected |
| `/send <session-id> <message>` | Start or steer work in a specific allowlisted session |
| `/status` | Send the selected session's status card |
| `/stop` | Interrupt the selected session's active turn |
| `/logs` | Show bounded, paginated local command logs |
| `/diff` | Show the bounded, paginated unified diff |
| `/help` | Show command help |

Selecting a session makes it the default for `/send <message>` and ordinary text. With no selected session, `/send <message>` behaves like `/new <message>` by creating a session in the chosen project and starting the message there. The explicit `/send <session-id> <message>` form selects and addresses another session. `/instructions` asks the live Codex app-server for its built-in presets, creates an empty session in the chosen or sole project when no session is selected, renders the presets as signed Feishu card actions, and applies the chosen preset to subsequent turns in the session without sending custom developer text. `/instruction` is accepted as an alias. PulseCortex continuously discovers Codex sessions that are loaded on its shared app-server and can accept direct input, including idle sessions launched after the daemon and sessions started from subdirectories of a registered project. A sole newly discovered session becomes the default and is announced in Feishu; otherwise Feishu asks the owner to choose through `/sessions`. Choosing a project adopts its newest controllable session except when completing a `/send` request that needs a new session. Multiple sessions can work concurrently, including sessions in different registered projects. If Codex requests structured input, PulseCortex sends selectable cards and accepts direct-message free-form answers when allowed. Secret-input questions are stopped locally and are never rendered into Feishu cards.

## Development

```powershell
pnpm protocol:generate
pnpm typecheck
pnpm test
pnpm build
```

Only regenerate the protocol with the supported Codex CLI. Review generated changes and update `SUPPORTED_CODEX_CLI_SERIES` only after contract and recovery testing.

Package boundaries:

- `domain`: normalized contracts, events, state rules, paths, and safe text
- `persistence`: SQLite migrations, audit/delivery state, signed interactions, command logs
- `codex-driver`: generated protocol snapshot and shared local WebSocket driver
- `feishu-adapter`: official SDK long connection, v2 cards, inbound normalization
- `core`: authorization and session coordinator
- `daemon`: supervised process entry point
- `cli`: `pulsectl` local administration
- `installer`: Windows, macOS, and Linux user startup integration

QQ is deferred until the domain interfaces stabilize; no QQ concepts belong in core.
